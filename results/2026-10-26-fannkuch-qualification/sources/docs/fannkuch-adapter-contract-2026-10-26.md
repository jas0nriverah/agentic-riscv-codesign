## Fixed workload and verifier

Use the pinned sequential C submission with its published correctness input,
`n = 7`. This executes all `7! = 5,040` permutations. Preserve both oracle
outputs exactly: signed checksum `228` and maximum flips `16`. The pinned
upstream function prints the checksum and returns the maximum; the upstream
`main` adds command-line parsing and formatting. Neither output may be dropped
or replaced by a checksum of a subset of iterations.

The hardware harness already calls `benchmark()` inside the cycle/instruction
counters and then calls `verify_benchmark(result)` outside the measured region.
The adapter should expose those existing functions without changing
`hardware/embench_firmware.c`:

- `benchmark()` runs the complete pinned algorithm once at `n = 7` and returns
  a checked 32-bit encoding in the existing `int` result channel. Require
  `sizeof(int) == 4`; reject with sentinel `-1` unless
  `-32768 <= checksum <= 32767` and `0 <= maximum_flips <= 32767`. Then encode
  `((uint32_t)(checksum + 32768) << 15) | (uint32_t)maximum_flips`. The bounds
  make the signed addition safe and prove the encoded word is at most
  `INT_MAX`. Include `<limits.h>` and `<stdint.h>`. Never shift a signed value
  or truncate before checking its range.
- `verify_benchmark(result)` first rejects negative values, decodes the upper
  16 bits as `(int)((uint32_t)result >> 15) - 32768` and the lower 15 bits as
  `((uint32_t)result & 0x7fffU)`, and returns success only for checksum `228`
  and maximum flips `16`.
- Initialization and warmup hooks are no-ops; they must not run the workload
  again or alter the timed input.

## Permitted adapter changes

The source listing is rendered HTML at the pinned commit, so any later
extraction must be a separately reviewed, deterministic source-generation step
with its own output hash and provenance. The adapter may change only the
program interface needed for freestanding execution:

1. Fix the input at `n = 7`; remove command-line parsing.
2. Expose the computed checksum to the wrapper (for example, by adding an
   output pointer at the existing terminal return) and remove host stdout
   formatting. Preserve the permutation initialization, every loop, flip
   count, maximum update, checksum update, and termination condition.
3. Remove the upstream CLI `main`; do not change the algorithm or the number
   of iterations.
4. Encode both results in the `benchmark()` integer return and compare both
   against the pinned constants in `verify_benchmark()`.

The change must be reviewed as an output/ABI adapter, not as an optimization.
The exact source diff is generated by counted, strict replacements in
[`build_fannkuch_adapter.py`](../scripts/build_fannkuch_adapter.py): replace the
host-only includes, add one checksum output parameter, replace the terminal
`printf` with that output assignment, remove the CLI `main`, and append the
checked wrapper and the two no-op hooks required by
[`embench_firmware.c`](../hardware/embench_firmware.c). The generator refuses
any missing or duplicate source fragment. Hashes for the HTML, extracted
source, adapter, and license are in
[`FANNKUCH_REDUX_PIN.json`](../benchmarks/fannkuch/FANNKUCH_REDUX_PIN.json).
