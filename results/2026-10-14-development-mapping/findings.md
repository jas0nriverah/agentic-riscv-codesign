# Bounded mapping descriptors: fitting-only V6 ablation

A fixed 23-descriptor block derived from existing **original generic bit-level
DAGs** reduced mean nine-stratum macro OOF MAE from **5.299425 to 4.935113 LUT4**
across three fixed seeds: **0.364312 LUT4, or 6.87455%**. All eight nonmultiply
strata improved on average; multiplication regressed. This supports the proposed
representation as development evidence. It does not establish application
transfer, calibrated bounds, an optimal mapping, or a production V6 model.

## What was fixed and tested

New code is limited to `isaforge/mapping_features_v6.py`,
`scripts/develop_v6_mapping.py`, `tests/test_mapping_features_v6.py` and
`tests/test_develop_v6_mapping.py`. Frozen V4/V5/external sources and outputs were
not changed. No test or external inputs/outcomes entered this study.

The original 1,665 fitting rows, five frozen component folds, original zero-graph
override, and existing feature matrix were reused. Every estimator uses 300
ExtraTrees, minimum leaf1, max_features1.0, one worker, seeds2026101421–2026101423.
There were 15 matched baseline and15 augmented fits, zero parameter search,
zero target mapping, zero feature synthesis and zero calibration fitting.
The three baseline prediction vectors reproduced the archived OOF vectors
**exactly**. No row was omitted because of its label, runtime, truncation or error.

`plan.json` fixed all input/runtime/helper hashes, software versions, frozen
Yosys identity, cache manifests/file hashes, exact rows/folds, three seeds and
feature names before feature extraction or fitting. Its SHA256 is
`1ce6e0226b976e2a57bed97144ec4a85220f3b6ff16acf548edf02ef5fa8c603`.
The runner checked these source/input hashes again after fitting and rehashed
every original graph. All1,665 expected original caches were present; missing
or mismatched caches fail closed and are never regenerated by this runner.

## Descriptors and approximation scope

The prototype accepts only single-bit AND/OR/XOR/NOT/MUX cells, defined0/1
constants, one flattened candidate module, and driven input/output signals. It
rejects unsupported cells, undefined bits, multiple drivers and cycles,
including cycles in disconnected logic. An iterative Kahn traversal avoids
recursive-chain limits. All experiment graphs passed; none had unreachable
cells. Features describe output-reachable implementation logic.

For each gate, the algorithm stores at most **eight nontrivial cuts with at most
four leaves**, plus its trivial cut for later merges. Intermediate merge states
also have an eight-state budget. States are ranked by retained-cut depth,
leaf count, sum of leaf area flow and deterministic bit-ID tie breaking, after
subset dominance pruning. A direct-fanin cut remains eligible even if earlier
partial-state pruning exhausts every combination. Budgets and tie breaking make
this an approximation, not exhaustive cut enumeration or an optimal solution.

The feature block records retained cut-size counts, alternative-cut count,
selected leaf/depth summaries, output area-flow proxies, a selected structural
cover count, exact multioutput ownership fractions, shared internal fanout,
reconvergent input-support fraction, exact structural output-root MFFC node
counts, budget truncation/drop/fallback counts, and unreachable gate count.
Physical aliases of the same driven output are deduplicated for these summaries.
MFFC reference decrements account for reconvergent branches and other output
references. Its count is **generic gate count**, never mapped local LUT area.

Area flow is `(1 + sum(leaf flows))/max(distinct-consumer fanout,1)` for the
selected structural cut. This borrows a standard mapping heuristic while
retaining this prototype's own generic-cell and fanout conventions. The block
does not perform Boolean matching, inverter-edge canonicalization, functional
truth-table reduction, cut expansion/iterative area recovery, dedicated carry
recognition, or FPGA technology mapping. Equal functions with different
implementations can therefore have different descriptors. No descriptor is an
SB_LUT4/SB_CARRY count or a certified lower/upper bound.

These choices follow established cut, MFFC and area-recovery concepts; there
is no algorithmic novelty claim. The relevant primary papers define feasible
cuts and MFFCs and explain why sharing, area flow and structural choices affect
LUT mapping. [Mishchenko et al., FPGA2006, sections2–5](https://people.eecs.berkeley.edu/~alanmi/publications/2006/fpga06_map.pdf).
The fixed small cut budget and ranking criteria follow priority-cut practice.
[Mishchenko et al., ICCAD2007, sections3.3 and4.1–4.4](https://people.eecs.berkeley.edu/~alanmi/publications/2007/iccad07_map.pdf).

Budget truncation occurred in929/1,665 rows (55.8%):234,396 gate instances had
truncation and525,839 nondominated merge states were budget-dropped. The direct
fanin fallback was used for279 nodes in20 rows. These are reported feature
values and retained limitations; truncated rows were not filtered.

## Validation, cost and reproduction

Seventeen focused tests pass. Handgraphs cover constants/wires, four- versus
five-input cone depth, reconvergent diamonds, exact MFFC reference behavior,
multiple outputs, duplicate aliases, unreachable nodes, cycles, unsupported
cells, missing drivers, unknown constants, actual budget truncation, exhausted
partial-state fallback and a1,500-gate chain. Every retained cut in the
budget-exercising fixture is independently checked to intercept every input
path. Runner tests reject missing/mutated caches, wrong formula identity,
undeclared seeds, repository outputs and overwrite attempts. Together with the
router/helper tests,27 tests pass.

The independent review agent also tested500 random DAGs/2,457 reachable gates:
selected cuts independently separated inputs, structural MFFCs matched a
separate reconstruction, and descriptors were finite/nonnegative. Its audit
covers the pre-fallback-counter22-descriptor revision; the added counter did
not change cut selection. Current23-descriptor focused tests also passed in
its source review. See `work/v6-mapping-independent-audit.json`.

Cached provenance validation plus descriptor extraction took20.89s on this
machine. The15 baseline fold fits took35.29s, the15 augmented fits40.93s.
The augmented view has217 columns versus194, approximately16% more measured
fit/predict time in this single sequential run. This is not an inference
benchmark: timing includes fitting, baseline always ran first per seed, and OS
caches/scheduling are uncontrolled. Original generic graph cache bytes read
were approximately304MB. A deployment would need a separately measured
view-aware extractor and model-memory/runtime assessment.
