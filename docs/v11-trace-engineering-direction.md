## Diagnosis supported by existing evidence

`collect_trace_external` connects Spike's commit FD to Python `parse_trace`, which matches/decodes each instruction and JSON-serializes it. `CountedTrace.write` immediately JSON-parses that same record again to count PCs and block starts, then Python gzip compresses it. This entire path runs before the pipe can drain, so Python/codec throughput can backpressure Spike. HTIF stdout is correctly separate and must remain so.

These are lower bounds on complete-window volume, not full instruction counts. Roughly170–195 thousand measured commits/second were retained across the fixed300-second capture attempts. The first500,000 AMMUNITION commits include substantial integer conversion/division; PM's sample is dominated by software float multiply/add. Such helpers are part of the declared computation and cannot be filtered away. Untraced selfchecks and exact O0/O2 snapshots passed; file-mtime gaps are not reliable simulator timing measurements. The surfaced cleanup `PermissionError` may mask the original termination context. Existing evidence establishes large streams and a synchronous processing path, not an exact bottleneck profile, guaranteed speedup, program nontermination, or a sufficient replacement budget.

## Smallest proposed replacement

Keep the frozen Spike, original O2 ELF, runtime, program inputs and instruction stream. Add a **new** capture helper, leaving the first collector, `tracing.py`, `CountedTrace` and candidate/fusion code untouched:

1. Open a fresh `.raw-spike.log.gz.partial` and independent HTIF/stdout and stderr files. Start one pinned native gzip-compatible compressor at fast level1, with its stdin connected directly to a raw byte pipe. Start the same Spike command with `--log-commits --log=/dev/fd/WRITE_FD`, passing only that FD. Its stdout still goes to the HTIF file. Use argument arrays, no shell pipeline. Close every unused parent FD immediately so EOF is observable. Python supervises processes but performs no per-instruction read, decode, JSON conversion or count during capture.
2. Retain the complete raw log, including startup, init and postmarker activity. No native PC filter, marker filter, sampling, instruction elision or kernel-only logging. Success requires Spike exit0, compressor exit0, EOF/trailer completion, and the exact original HTIF snapshot/oracle result. Record command arrays, tool identities, exit codes, elapsed times, bytes and hashes. Promote only to **captured**, not yet validated. Compressor/disk failure, timeout or interruption leaves named partials and an explicit failed stage.
3. Offline, stream-decompress that captured raw log through the **unchanged** `parse_trace` and `CountedTrace` into a fresh decoded gzip JSONL partial. This retains the original global raw-line `seq` indices and exact decoder semantics; it also preserves the existing PC counts and discontinuity boundaries without a second trace run. Do not prefilter even harmless-looking raw lines: they affect `seq`, and malformed `core` lines must still fail. Validate the whole raw stream through EOF, not just the region between two observed markers.
4. Require exactly two instret markers with destination values, modulo32-bit `instret_delta == measured_commits + 1`, zero unknown measured instructions, valid gzip CRC/EOF, matching HTIF output and a matching unchanged ELF hash. Call `CountedTrace.finish`, add the same static symbol boundaries, then invoke unchanged `extractCandidates(..., maxSize=4, limit=None)` and the same16-vector/seed2026101507 fusion checks with zero opaque skips. Only then promote decoded evidence to validated/complete. A valid gzip alone never establishes a complete window.

The compressor must be selected and its executable/version and relevant runtime identity bound before any future attempt; no candidate compressor was executed or benchmarked here. This design removes Python work from capture but does not guarantee completion: compression, disk or Spike logging may still dominate. The offline path deliberately keeps the first decoder and counter; optimizing that path is a separate future change, not part of the minimum design.

Own both processes and their sessions explicitly. Supervise early compressor failure as well as Spike exit. On failure, close pipe ends, terminate only still-live owned process groups, and reap both children within a bounded cleanup period. Preserve the primary exception and all cleanup exceptions separately, including `PermissionError`; cleanup must not overwrite the root cause. Record PID/session ownership and verify that no owned child remains. Do not delete failed compressed/raw/decoded files or append to an earlier attempt.

## Proposed resource envelope, not an active budget change

Retain the original300-second **capture** deadline for a proposed first spool attempt; count it from launch through Spike termination. A separately reported compressor drain/reap allowance could be30seconds. Offline decoding/extraction/fusion needs a separately sealed limit—propose1,800seconds per failed program initially—because moving work after capture changes the accounting even when the execution/capture deadline stays300seconds. Report total wall time and CPU/IO time by stage; do not compare capture-only time against the original end-to-end trace time as a speedup.

Complete volumes are unknown. For capacity planning, the observed decoded format needs about10.2GB uncompressed and1.0GB gzip per100million commits; compression ratios are empirical and may change. Raw Spike line size/compression has not been measured. An illustrative80–160bytes/commit means8–16GB raw text per100million commits, not a proven bound. Retain compressed raw plus decoded evidence; never materialize a whole uncompressed log. A candidate storage policy is16GiB compressed raw plus16GiB decoded per program, with at least64GiB free for one sequential job and existing evidence. The supervisor must enforce the byte limits and preserve an incomplete attempt if reached. These are reviewable engineering caps, not predicted completion requirements or authorization to use them now. Do not extend them automatically after seeing progress.

The exact reservation stays `ammunition`, `audiobeam`, `pm`, `fmref`, `fac`, `recursion`, with the original five-family mapping and fac/Fibonacci together in one family. Reuse the original hash-verified O2 ELF for any proposed recovery capture; no recompile, flags, source, input, initialization, marker or math-library change is needed. Recovered windows must include all called helpers and all eligible formulas/occurrences, with no top-K, cuts, ranking or postlabel selection. No scientific input, candidate interface, original circuit target or model changes. No ML features/predictions/area measurements are released by this engineering proposal.

Even recovering AMMUNITION and PM would not restore the original complete five-family, equal-program-within-family area-MAE endpoint: an empty program has undefined MAE. Preserve it as a coverage outcome. Do not replace Fibonacci, change its fixed input, enlarge candidate bounds, omit its weight, or call an observed-subset result the original primary. Any different error endpoint requires a transparent prospective amendment before labels, retaining the original failed/incomplete endpoint and all six coverage outcomes. The current at-least-four-family input feasibility gate is not met; runtime recovery and scientific endpoint validity are separate questions.

## Validation expected before a recovery release

First test new process supervision using deterministic fake producers/compressors: stdout/commit separation, early compressor exit, producer failure, blocked pipe, timeout, interruption, partial preservation, FD closure/EOF, disk/byte limits and independently injected cleanup errors. Test raw fixtures with missing/third markers, malformed commits, missing marker register values, wrong delta, 32-bit counter wrap, unknown instructions, truncated/corrupt gzip and trailing errors after the stop marker. A successful fixture must replay every decoded field including `seq`, complete PC counts, discontinuity/final boundaries and exact snapshots.

Replay the retained successful V11 decoded traces to recheck PC counts, boundaries, entire candidate metadata/overlap-safe merit and fusion results without rerunning workloads. Synthetic raw-to-decoded fixtures validate the new spool/decoder interface; the old normalized JSONL does not reconstruct an authentic original raw Spike log and must not be represented as one. Only after source/tool hashes, supervision tests, invariant replay and the proposed stage/storage caps are independently reviewed should a separately authorized recovery capture be considered. No retry is performed by this note.
