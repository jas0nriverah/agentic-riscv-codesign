# Primary-method notes: custom-instruction selection and hardware representations

Reviewed October 22, 2026. This supplements, rather than changes, [research-foundation.md](research-foundation.md) and [selection-methods-review.md](selection-methods-review.md). The review used current web discovery and primary author, proceedings, publisher and institutional sources. No model fit, native hardware job or frozen evidence change was performed. All eleven ISAForge source groups are consumed development data. These notes make no novelty or superiority claim.

The adaptation target is the existing RV32I/ILP32 PicoRV32 system, two-input/one-output PCPI pipeline, original integrated 8 KiB RAM, recorded compiler settings and 12 MHz feasibility threshold. Newer BEEBS contexts retain `-Os` and the 6400/6528 memory partition. A paper's larger register interface, caches, memory ports or arithmetic ISA must not silently change that target.

## What the closest methods actually optimize

**CIDRE — ICCAD 2025, author manuscript arXiv:2509.15782v2, December 15, 2025.** Read §§II-D–III, Algorithm 1 and §IV. It exhaustively enumerates constrained binary-level RISC-V subgraphs, canonicalizes operand-sensitive graphs, and integrates suggestions into an nML processor before synthesis. Immediate encoding constraints are explicit; excess immediates can be hardcoded. Selection combines frequency-weighted instruction savings, overlap-aware covering and one-step lookahead. Each proposed extension is synthesized; the search rejects estimated application runtime worse than baseline and considers alternatives when the clock lengthens. Runtime is remaining instruction count multiplied by synthesized clock period, with all instructions assumed single-cycle; faster-than-baseline clocks earn no credit. Evaluation uses a three-stage RV64IM processor and integrated processor area, not isolated primitive area. This is the closest timing-aware comparator, but its CPI assumptions and additional I/O configurations cannot be copied into PicoRV32. A PCPI adaptation must use calibrated processor latency, two inputs/one output, and our integrated synthesis boundary. Our current merit control is not a CIDRE reproduction. [Full primary methods](https://arxiv.org/html/2509.15782v2); [publication DOI](https://doi.org/10.1109/ICCAD66269.2025.11240781).

**CIExplorer — ICS 2025, DOI 10.1145/3721145.3730421, 16-page proceedings paper.** Read §§3–8 and §9.1–9.2. A genetic seed-growth method finds recurring graphs with identical operation counts/types; split-and-combine handles remaining regions. LLVM IR specialization inserts custom and operand-moving instructions. A static event-dependence graph models pipeline, data, resource and execution-port dependencies; profiled basic-block counts weight estimated speedups. Selection removes overlapping candidates with a weighted independent-set analysis. The search model assumes L1 hits and fixed control flow. Evaluation uses an in-house cycle-level LLVM-IR simulator, representative 50-million-instruction chunks, and GEM5-SALAM custom-datapath area. It does not establish routed whole-processor timing. Importantly, its in-order DEG ablation is nearly tied with simple merit (17.3% versus 17.2% cycle reduction); larger gains from the detailed model concern out-of-order processors. Our single-issue PCPI context does not justify importing its OOO model or relaxed operand interface. The useful lesson is to cost the actual lowered code and communication, not merely the selected expression. [Full primary proceedings PDF](https://hpcrl.github.io/ICS2025-webpage/program/Proceedings_ICS25/ics25-61.pdf).

**ISAMORE — ASPLOS 2026, DOI 10.1145/3779212.3790162, author-hosted 15-page proceedings PDF.** Read §§3–6, §7.1 methodology and §7.2.2–7.2.3. Phase-oriented equality saturation and anti-unification find reusable semantic patterns; structural hashing, typing and sampling control search growth. Hardware-aware Pareto selection uses a bounded beam and extraction/refinement. Software benefit sums profiled basic-block cycles-per-operation; hardware latency comes from ASAP HLS scheduling, including loop pipelining, and area is additive across HLS patterns. The HLS engine uses XLS regression-based operator estimators. Most reported performance-study speedups are that model’s estimates; final pattern areas use OpenROAD/ASAP7. The main profiling core is cached out-of-order ARM, with loose RoCC-style memory access. Separate Rocket/RoCC case studies use RTL simulation and physical implementation, including frequency overhead. Therefore its semantic-reuse idea is relevant, but its broad interface and additive cost equations are not our measured PCPI label contract. A new e-graph framework is unnecessary for testing better semantic descriptors on our existing formulas. [Full author PDF](https://uv-xiao.github.io/assets/pdf/isamore_asplos26.pdf); [author implementation](https://github.com/isamore-group/ISAMORE).

**Clay — ICCAD 2025, DOI 10.1109/ICCAD66269.2025.11240669, author-hosted nine-page proceedings PDF.** Read §III-C–E and §IV-A–C, including Tables III/V/VI. Clay describes instructions and chooses implementation coupling/scheduling, rather than discovering a bounded candidate pool. Its ILP minimizes weighted latency and result lifetimes subject to dependency, stage and resource constraints; coprocessor loops can use modulo scheduling. It evaluates cacheless five-stage RV32I Clay-core and RV32IMAC Rocket/RoCC, with Verilator cycles and synthesis area/period; Rocket caches are removed for area/timing comparison. Its combinational CORDIC examples show that large cycle reductions can accompany severe clock degradation. Stateful memory access and custom registers exceed our current PCPI contract. Its applicable lesson is architectural-context-specific resource/timing accounting, not a replacement ML selector or a portable area dataset. [Full author PDF](https://uv-xiao.github.io/assets/pdf/clay_iccad.pdf); [author project](https://github.com/pku-liang/clay).

**Sovietov — arXiv:2401.00772v1, January 1, 2024.** Read the algorithms and evaluation on PDF pp.3–10. Iterative MISO clustering can recompute shared operations inside multiple clusters. A CEGIS/SMT subsumption check searches argument permutations and constants that make one instruction implement another. RV32I compiler-model experiments report compiled-code size and instruction-set cardinality. These are not integrated area, routed timing or whole-program cycle measurements. Semantic equivalence/subsumption can help duplicate-family screening; its reported improvements do not establish a paid-query selection baseline for our context. [Exact primary version](https://arxiv.org/pdf/2401.00772v1).

## Established support for constant-aware representations

**BitValue — Budiu and Goldstein, CMU-CS-00-141, June 2000, full 28-page technical report.** Read §2, examples in §3, §5 and Appendix A. This exact report is distinguished from the abridged Euro-Par paper. A four-element per-bit domain represents zero, one, unknown and irrelevant bits. Conservative forward transfer propagates constants; backward transfer propagates bits irrelevant to the visible outputs. Signedness accompanies the bitstrings. Alternating dataflow passes reach a fixed point. The hardware evaluation counts required bit-level operations for reconfigurable targets; it is not an integrated FPGA-SoC area predictor. This supplies established algorithms for extracting semantic facts, without asserting that those facts alone predict our LUT deltas. [Full primary report](https://www.cs.cmu.edu/~seth/papers/budiu-tr00.pdf).

The current **XLS primary engineering documentation**, rather than a new peer-reviewed result, gives a concrete implementation precedent. Its optimization overview describes known-bit propagation, demanded narrowing, constant shifts, comparison simplification and Boolean simplification. Its delay methodology sweeps synthesized operations over widths, fits linear/logarithmic/constant terms, and discusses fanout, reconvergence and whole-network approximation errors. These are reasons to retain widths and constants in a representation; an ASIC operator model is not a calibrated iCE40 LUT4 or integrated-core predictor. The general optimization overview was read; the separate pass catalog explicitly warns that its generated descriptions are not human verified, so it is not relied upon. [Optimization methods](https://google.github.io/xls/optimizations/optimizations/); [delay estimation methods](https://google.github.io/xls/delay_estimation/).

## Implications for the next bounded experiment

The strongest immediately usable performance control remains our independently calibrated PicoRV32 latency merit: every one of the 87 measured cycle deltas currently agrees exactly. CIDRE supplies the most relevant integration/timing selection precedent. A faithful adaptation would retain actual lowering, executable occurrence counts, integrated area, minimum routed Fmax, overlap-aware covering and baseline fallback. It would not identify raw instruction-saving merit with the complete published algorithm. No benefit-residual learner is supported by zero observed residuals.

The expint development failure isolates a representation hypothesis. For u32 input `x`, candidate 00 is

```text
p = (x <u 1)                  // 0 or 1; equivalent to x==0
((0-p) & 998)  + 2               // exactly x==0 ? 1000 : 2
```

It has only two possible output words and seven changing bit positions (`1000 xor 2 = 0x3ea`), despite four syntactic operations. Candidate 07 is `4-x mod 2^32`, a full-width bijection despite two operations. This algebra does not identify the integrated netlist cells responsible for +17 versus +101 LUT4, and does not prove a new descriptor improves selection. Plain known-bit analysis also misses some relationships between repeated copies of the same predicate; Boolean-to-mask structure or a conservatively proven small value set can carry additional information.

The smallest defensible ML change would therefore be **one preregistered semantic feature block**, keeping a fixed existing learner/acquisition, calibrated latency, all strong controls, hardware context and budgets. Candidate features can include proven known/demanded bits, signedness, operand/output effective widths, constant versus variable shifts, constant-minus-input orientation, comparator results, and Boolean-mask/two-value structure. Facts must hold over the complete supported operand domain, not only observed benchmark values. Keep original RTL/formulas unchanged, and use semantic equivalence for leakage grouping as well as representation.

Before any fresh test, diagnose the feature computation on consumed data and preserve its negative results. Freeze one revision and test on new independent source families with useful dynamic opportunities and genuine area/timing boundaries. Report feasible-performance regret and failed-query rate; do not select a feature bundle by sweeping the 87 consumed outcomes. An integrated-netlist cone inspection could explain the motivating LUT contrast without retraining, but it would remain diagnostic. Adding a GNN/RL enumerator, replacing the RTL flow, or treating summed isolated costs as the primary label is not the next step.
