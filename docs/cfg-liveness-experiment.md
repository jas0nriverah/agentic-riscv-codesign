# General candidate coverage with static register liveness

This is an engineering coverage experiment, not another learned model or candidate-enumeration algorithm. Reuse the existing connected dataflow enumeration and two-input/one-live-output constraints. Add standard backward static CFG liveness to distinguish dead temporary register writes from outputs that the rest of the program needs.

## Demonstrated gap and fixed scope

The [original Lift qualification](../results/2026-10-25-lift-qualification/qualification.json) remains rejected: 15 legal source-mapped formulas become 11 after the correct relocation guard, below the declared twelve-formula pool. Calibration excludes none. The run reaches no candidate measurements or hardware baseline. Preserve its exact sources, archive and first rejection; never rerun or relabel that context as accepted.

Two original controller loops show why coverage can improve. They convert a loaded value to Boolean and OR it into another register. The Boolean temporary is overwritten before any read on both static successors, including the backedge. The existing block-local extractor conservatively treats every last register write as an output and rejects those cuts. The existing full-register verifier independently rejects the changed dead register, so extraction alone must not be relaxed.

The new procedure must:

- Derive successors and use/def sets from the complete decoded static program, retaining both conditional edges. Iterate live-in/live-out to a fixed point. Never infer deadness from observed execution counts.
- Fail closed at unresolved calls, returns, indirect jumps, unknown effects, invalid/gapped targets or exits. Preserve x0 semantics. A missing proof must retain a register as live.
- Outgoing liveness alone cannot rule out an unobserved jump into a removed instruction. Protect every static branch/direct-call target and call continuation as a block entry. Refuse extraction globally for unsupported indirect transfers or malformed/unknown control. Canonical `jalr x0,x1,0` returns require an explicit caller option, disabled by default and independently authenticated in the certificate. The Lift adapter may opt in under its exact bound ordinary compiled-C ABI context; this assumes standard return discipline and is not an arbitrary-binary control-flow proof. Calls/returns remain all-live barriers. Function pointers, computed goto, coroutines and unresolved indirect calls stay unsupported; rejection is preferable to widening these assumptions for one source.
- Existing firmware uses standard adjacent AUIPC/JALR direct calls and counter-read markers. Recognize only a matching raw call pair writing link register x1, with a resolved aligned in-program target and no possible static entry into JALR bypassing AUIPC. Check this after collecting all direct and resolved targets, including targets from other call pairs. Preserve call barriers and protect callee/continuation entries. Recognize only exact read-only CSRRS forms for cycle/cycleh/instret/instreth as opaque, all-live, non-control barriers; never fuse or cross them. Other indirect/unknown forms remain rejected. These are existing [RV32 control-transfer](https://docs.riscv.org/reference/isa/v20260120/unpriv/rv32.html) and [counter-read encodings](https://docs.riscv.org/reference/isa/_attachments/riscv-unprivileged.pdf), not new ISA or compiler behavior. Reserved encodings, mismatched pair registers, second-word entries, CSR writes and missing targets need explicit negative tests.
- Reuse existing connectivity, contribution, two-input, single-result, input-lifetime, source-statement, overlap, relocation and calibration checks. The custom instruction still executes at the final member. No new memory/control operations, opcodes, compiler flags or RTL behaviors are introduced.
- Independently rederive the complete program/source/CFG certificate and candidate legality during verification and discovery authentication. Retain exact memory/control equivalence and every live register; differences are allowed only in eliminated writes proved dead. Use an explicit new verification schema, not a passing result from the frozen full-register verifier.
- Bind new sources and this contract in a distinct context and entrypoint. Existing entrypoints must reject it. Scoped integration must restore all reused bindings after nesting, errors and interruption. Never modify hash-bound extractor, verifier, controller or historical results.

Required tests cover both branch edges, overwrite on only one path, join-path use, backedges, address/store/branch reads, intervening input overwrites, unknown/indirect/call barriers, missing targets, source and certificate tampering, and restoration. Sampled block equivalence and recorded-input processor correctness are not universal program proofs.

## Stages and acceptance

First validate pure analysis/extraction/reverification against synthetic cases and archived assembly/profiles, with zero compilation, synthesis, candidate labels or model fitting. Count gains and losses explicitly. A predicted 11→13 Lift formula change is a hypothesis until recomputed.

Only after review, tests and a pushed source contract may a separate coverage-context qualification run on unchanged Lift inputs. Keep RV32I_zicsr/ILP32 `-Os`, 8 KiB RAM, 6400/6528 partition, one-wait PCPI, twelve-formula stratification, joint >=0.5% / ten-execution opportunity gate, original 1,001 iterations and checksum 4005888. Preserve any new rejection. The qualifier may measure the unextended baseline but must refuse all candidate dispatch.

Lift has already informed this engineering improvement through public static/profile evidence; it must not count as an untouched confirmatory source for model superiority. A later candidate collection requires its own complete pushed model/controller release before labels, shared information/budgets, all failed-attempt costs and actual correctness/whole-program/hardware outcomes. Qualification acceptance alone adds no training labels. Independent untouched source families remain necessary for the active research goal.
