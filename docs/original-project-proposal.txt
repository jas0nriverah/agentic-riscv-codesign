ECE 4803 AI for Engineering Project Proposal
Agent-Guided Custom Instruction Selection for RISC-V Using Learned Prediction
 Sooraj Tharumia, Jason Rivera-Hernandez, Yuuto Matsuki

1. What We Are Doing
RISC-V lets designers add custom instructions. If a program repeatedly runs the same short chain of operations, that chain can be fused into one instruction so the program runs faster. Each custom instruction costs a chip area, so a design can afford only two or three, and choosing which chains to build is hard. The standard method picks the most frequent chains and ignores hardware cost. which can cancel the benefit. The only reliable check is to build each candidate in hardware, which is too slow to do for all of them.
2. How We Are Going to Do It
We run standard benchmarks on a RISC-V simulator and look for short chains of instructions that repeat often enough to be worth fusing into one.
For each candidate, we calculate how many cycles it saves, how much it slows down the processor's clock and how much chip space it uses. Combining these gives the real speedup, not just how often the chain shows up.
Building every candidate in hardware is slow, so we train a machine learning model on easy-to-measure features, like chain length and instruction type, to predict a candidate's speedup and area without building it. The model also gives a confidence score, so we know when to trust its guess and when we don't.
An AI agent picks the final set of instructions to fit the chip's space budget. It leans on the model's predictions when confidence is high.
We build the top picks into a real RISC-V processor and measure the actual speedup and chip space, to confirm the predictions held up.
3. Expected Results and Contribution
Frequency ranking will disagree noticeably with true speedup, and some frequent chains will produce little gain or a net slowdown.
The predictor will rank unseen candidates well enough to filter out poor ones. It will not be perfect, so the confidence estimate is a key part of the result.
Agent-selected instructions will beat frequency ranking and approach the oracle with far fewer hardware evaluations. If the agent gives little advantage over the simpler method, that is still a useful finding about when an agent is worth using.
Hardware results will follow the predicted ordering of methods, with some gap from prediction error.
Deliverables: A dataset of candidates with measured speedup, delay, and area; a trained predictor with confidence estimates; a selection agent compared against three baselines; and hardware-verified results.

ECE 4803 Project Proposal
Agent-Guided Custom Instruction Selection for RISC-V Using Learned Speedup Prediction
Sooraj Tharumia, Jason Rivera-Hernandez, Yuuto Matsuki
Problem Statement
A processor runs programs as long lists of simple instructions. RISC-V leaves room for designers to add their own. If a program keeps running the same short chain of instructions, where each step uses the previous step's result, that chain can be combined into one custom instruction, so the program runs fewer instructions. Finding these chains is a solved problem. The hard part is choosing which ones to build, because each one costs chip area and only two or three can realistically be added.
Today, candidates are ranked with a merit score: instructions saved multiplied by how many times the chain runs, keeping only chains that fit the instruction format's input and output limits [1, 2].
merit = (chain length − 1) × times the chain runs
This score counts steps saved but ignores hardware cost. A combined instruction can be a slow circuit, and the processor's clock must slow down to match its slowest instruction, which makes every instruction slower. In one reported case this completely erased the benefit of a candidate the score favored [2]. The score also depends on which input was used for counting, and it judges each candidate alone even though candidates affect each other. Measuring real benefit means building and synthesizing each candidate, which is too slow to do for all of them, so the field relies on the score [3].
Related Work
RL-GNN-CI uses reinforcement learning to pick custom instructions [6]. LACE uses LLM agents to implement instructions a designer has already chosen [7]. Regression models trained on a small number of simulations can predict processor performance accurately [4, 5]. Our project differs by predicting real, timing-aware speedup with a confidence estimate, and by testing whether an agent using those predictions chooses better than a standard method without an LLM. [Confirm how RL-GNN-CI measures benefit]
Approach
The project is a pipeline of seven stages. Each stage feeds the next.
1.	Run the programs. We compile eight integer programs from the Embench benchmark suite [8] for 32-bit RISC-V and run them in Spike, the standard RISC-V simulator. Each program checks its own output, so we always know whether it still works.
2.	Record and find candidates. Spike logs every instruction a program executes (a trace). A script scans the trace for chains of two to four connected instructions and keeps only chains with at most two inputs and one output, which is what a standard instruction allows. We expect about 30 candidates per program.
3.	Measure each candidate. Each candidate has a benefit and a cost. The benefit, steps saved, comes directly from the trace. The cost comes from writing the chain as a small circuit and synthesizing it with Yosys and nextpnr, which report its delay and area. We combine them into a real speedup:
speedup = (old steps × old clock period) ÷ (new steps × new clock period)
 new clock period = the longer of the old period and the circuit's delay
This gives one table row per candidate, about 240 in total [confirm after first run], and that table is the dataset for the rest of the project. About 25 candidates are also checked on the full processor to confirm the estimate holds.
4.	Check the premise. In week 4 we compare the merit score against real speedup for 30 candidates. If they disagree, the premise holds. If they line up, we add harder programs before going further.
5.	Train the predictor. A supervised regression model learns to predict a candidate's real speedup without synthesizing it. Its inputs describe the software side (chain length, times run, number of places it appears, loop depth) and the hardware side (operation types such as multiplies and shifts, and circuit depth). Using quantile regression and a Gaussian process, it also reports how confident it is [10]. We train on seven programs and test on the eighth, repeating for each program.
6.	Let the agent choose. An LLM agent gets a goal (choose the best set of instructions within a chip area budget) and a limited number of synthesis runs. It has four tools: list candidates, predict a candidate's speedup, measure a candidate, and choose a final set. We compare it with a standard active learning loop that uses the same predictor and budget but no LLM, to see whether the agent's reasoning helps.
7.	Build the winners. For the top two or three instructions, we give each an encoding in RISC-V's custom-0 opcode space, add it to Spike as a plugin, rewrite the program to use it, and confirm the output is still correct. We then build each into the VexRiscv processor using CFU Playground [9], simulate it, and synthesize the full design for area and timing.
Evaluation
We compare five ways of choosing instructions: the merit score, frequency ranking, random choice, active learning, and the agent. An oracle that measures every candidate gives the best possible choice. The main result is how close each method gets to the oracle for a given number of measurements.
We also report how well predicted and real rankings agree (Spearman correlation), whether the model's confidence ranges are accurate (calibration), and average whole-program speedup across benchmarks. The agent is run five times because LLM results vary. For the instructions we build, we compare predicted, estimated, simulated, and real hardware speedup.
